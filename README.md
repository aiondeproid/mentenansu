# 前処理 設備保全アプリ（プロトタイプ）

紙・Excel の「機械メンテナンス履歴（前処理1.xls）」をデジタル化する試作品。
画面構成は MENTENA（作業計画/履歴）を参考にしています。

## コンセプト

| 項目 | 内容 |
|---|---|
| 目的 | 設備ごとに分かれた履歴を1か所で検索でき、交換時期を見逃さないようにする |
| 利用者 | 設備課（PC で記録・管理）、現場（タブレット・スマホでその場で入力）、管理職（閲覧） |
| 動作環境 | 社内サーバー（Python + Flask + SQLite）。ブラウザから利用 |

### 機能

- **作業計画/履歴**: 全設備の履歴をキーワード検索（半角カナと全角カナを区別しない）、設備・区分・作業状況・期間で絞り込み、CSV 出力
- **交換アラート**: 定期項目ごとに「経過日数」「稼働時間（アワーメーター）」の両方で期限を判定。「実施を記録」から作業を登録すると前回実施日が更新される
- **部品・研磨管理**: フィルタースクリューなどをシリアル単位で管理。研磨回数（上限10回）、状態（使用中・予備・研磨中・使用禁止・廃棄）、交換履歴
- **設備台帳**: 設備情報、取引業者、アワーメーター入力、定期項目、作業履歴のタイムライン
- **分析**: 年別の定期・不定期件数、設備別のライン停止時間、故障内容のキーワード、設備別の故障件数

## 起動方法

```bash
pip install -r requirements.txt
python import_xls.py            # 前処理1.xls を data/maintenance.db に取り込む（初回のみ）
python app.py                   # http://<サーバーのIP>:5000/ で公開
```

- 取り込み直す: `python import_xls.py --reset`（アプリで入力したデータも消えるので注意）
- ポート変更: 環境変数 `MAINT_PORT`、DB の場所: `MAINT_DB`

## Excel 取り込みのルール

- 1 シート = 1 設備。「原紙」「Sheet1」「ﾐｰﾄｾﾊﾟﾚｰﾀｰｽｸﾘｭｰﾌｨﾙﾀｰ」は設備として取り込まない（研磨管理シートは部品マスタの初期値として使う）
- 日付は Excel 日付・`23.1.28`・`2022.11.19` などを統一する。`2015年` のような年だけの表記、`20.18.5.8` のように読めない表記、前の行より大きく遡る日付には **要確認** の印を付ける
- 「実施稼働時間」欄は、数字だけ・`○○分` のものを **ライン停止時間（分）**、`○○h` のものを **部品の稼働時間** として扱う
- 備考に書かれた `稟議 (280万)` などは費用として読み取る
- 定期項目の間隔は、履歴と備考から読み取った **仮設定** を含む（`import_xls.py` の `RULE_SEEDS`）。現場で確認したうえで画面から修正すること

## プロトタイプとしての制約

- ログイン機能はない。記入者は画面右上の欄に入力する（ブラウザに保存される）
- 写真の添付、承認フロー、通知（メール等）は未実装
- 取り込んだ履歴は 2025 年までなので、日数基準の定期項目はほぼ「期限超過」と表示される
- アワーメーターは手入力。前回実施時の値は、定期項目に紐づけた作業を完了で保存したときに記録される
