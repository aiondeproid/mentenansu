# 設備保全アプリ（プロトタイプ）

紙・Excel の「機械メンテナンス履歴（故障、定期点検記録簿）」をデジタル化する試作品。
画面構成は MENTENA（作業計画/履歴）を参考にしています。

## コンセプト

| 項目 | 内容 |
|---|---|
| 目的 | 設備ごと・職場ごとに分かれた履歴を1か所で検索でき、交換時期を見逃さないようにする |
| 利用者 | 設備課（PC で記録・管理）、現場（タブレット・スマホでその場で入力）、管理職（閲覧） |
| 動作環境 | 社内サーバー（Python + Flask + SQLite）。ブラウザから利用 |

### 機能

- **エリア切り替え**: 画面右上で前処理・後処理・原動機などを選ぶと、全画面がそのエリアに絞り込まれる（ブラウザに記憶）
- **作業計画/履歴**: 全設備の履歴をキーワード検索（半角カナと全角カナを区別しない）、設備・区分・作業状況・期間で絞り込み、CSV 出力
- **添付ファイル**: 作業記録に PDF・写真（JPEG/PNG、1ファイル30MBまで）を添付できる。`data/record_files/` に保存。記録や添付を消してもファイル本体は残す（バックアップから戻せるように）
- **工事点検計画**: 月カレンダーと年間計画表（定期項目 × 12か月、印刷可）。カレンダーには「予定（日付を決めた未完了の作業）」「期限（定期項目の次回期限）」「見込み（期限どおりに実施した場合のその次）」「実績」「故障」を表示する
  - 予定は作業記録を「未着手」で登録したもの（実施日 = 予定日）。完了にすると前回実施日が更新され、次の期限が出る
  - 期限を過ぎた定期項目は「期限超過・予定未定」の一覧に出るので、日付を決めて予定に入れる（カレンダーへのドラッグでも可）。予定・期限もドラッグで日付を動かせる
  - 稼働時間だけで管理する項目は日付が決まらないためカレンダーには出ない
- **交換アラート**: 定期項目ごとに「経過日数」「稼働時間（アワーメーター）」の両方で期限を判定。「実施を記録」から作業を登録すると前回実施日が更新される
- **部品・研磨管理**: フィルタースクリューなどをシリアル単位で管理。研磨回数（上限10回）、状態（使用中・予備・研磨中・使用禁止・廃棄）、交換履歴
  - **部品一覧（価格表）** タブ: 交換部品・消耗品の単価を区分（ライン）ごとに表示。設備に紐づけた部品は設備台帳の詳細にも出る
  - **Excel出力 / Excel取込**: 部品一覧と研磨管理部品を 1 つの .xlsx で書き出し、直したファイルを読み込む。取り込み前に追加・変更・削除の内容を表示し、エラーがあれば取り込まない（`parts_catalog.py`）
- **設備台帳**: 「エリア → 種類」または「種類だけ」でグループ分けして表示（グループごとに開閉、種類チップで絞り込み、カード／一覧の切り替え）。詳細画面では設備情報、取引業者、アワーメーター入力、定期項目、作業履歴のタイムライン
  - **Excel出力 / Excel取込**: 全設備を 1 つの .xlsx で書き出し、まとめて追加・修正して読み込む。取り込み前に追加・変更の内容を表示し、エラーがあれば取り込まない。削除はできない（状態を「廃止」にする）（`equipment_xlsx.py`）
- **測定機器**（サイドバーの設備台帳の下）: 「測定機器毎の管理台帳.xls」の秤量器・ノギス・温度計・加熱装置付属の温度計・製品保管庫の庫内温度計シートを取り込み（種類ごとにタブで切り替え。ノギス・温度計・加熱装置付属温度計は使用エリアの言葉で前処理／後処理／品管／タレ工程に振り分け（凍結後は後処理、受入・解凍・配合は前処理）、型式欄の「製造番号⏎型式」は分けて入れる）、№・ランク・プラント・工程・メーカー・型式・最大秤量・表示目量・購入日などを一覧にする。エリア（№の頭が「前」→前処理、「後」→後処理。予備機はどのエリアでも出る）・状態・ランク・キーワードで絞り込み。1 台ごとに故障・修理・新規購入などの履歴を記録でき、状態（使用中・故障中・運休・予備・廃棄・欠番）も一緒に変えられる
- **校正**（測定機器の「校正」タブ）: 検査・校正の記録書をアプリで記入・印刷する。様式は「保管庫の庫内温度計、作業場室温計の検査記録書」（庫内・室温計 11 台。`python calibration.py` で記録書の xls から測定機器に登録）、「製品保管庫の庫内温度計の検査記録書」（NF-102-器-026-05）、「CCPモニタリングに用いるタイマーの校正記録」（NE-023-001。加熱装置ごとに設定時間①と実測時間②を入れると差異（②−①秒）と判定（±2.00秒以内で合）を計算）、「蒸煮コンベア速度校正記録」（NE-023-002。5回分の設定周波数・基準通過時間①・実測通過時間②から差異（(②/①−1)×100％）を計算し、5回とも±1％以内で合）の 4 つ。温度計の様式は以下のとおり。検査年月日・検査者・使用基準器（温度計の台帳№）と、庫内温度計ごとの日常点検・冷蔵区／冷凍区・基準温度計の表示と補正温度（Ａ）・庫内温度計の表示温度（Ｂ）を入れると、最小表示に合わせた処理（0.1℃そのまま／0.5℃二捨三入／1.0℃四捨五入）・器差（Ｂ−処理後）・判定（±2.0℃以上か日常点検否で否）・補正温度（−器差）を自動で計算する。保存すると各機器の履歴にも「校正」が残る（検査記録を直す・消すと一緒に変わる）。対象の庫内温度計は台帳の「26製品保管庫の庫内温度計」シートから取り込む（`python instruments.py --kind 庫内温度計`）。印刷は一覧・検査記録の「印刷」で紙と同じ並びの A4 横 1 枚を開く（/print/calibrations/<id>。「白紙を印刷」で手書き用の白紙も出せる）。様式を増やすときは calibration.py の FORMS に足す
  - 取り込み: `python instruments.py`（`--dry-run` で読み取り結果だけ表示）。№で突き合わせて上書きするので何度流してもよい。台帳から読んだ履歴は入れ直し、アプリで足した履歴は残す。**状態や機器情報をアプリで直した分は取り込み直すと台帳の値に戻る**
  - 台帳右側の経緯メモ（「18.11.8故障18.11.20新規」など）は日付ごとに区切って履歴にする。原文は詳細画面の「台帳の記載」に残る。`19.720` のように読み方があいまいな日付は **要確認**
  - 状態は経緯メモから推定（最後の記録が廃棄→廃棄、故障だけ→故障中、日付のない「運休」→運休、中身のない行→欠番、末尾の数字だけの番号は「予備1」〜として予備）。現場で確認して直すこと
  - **Excel出力 / Excel取込**: 全測定機器を 1 つの .xlsx で書き出し、まとめて追加・修正して読み込む。取り込み前に追加・変更の内容を表示し、エラー（種類と№の重複、使えない状態・エリア、読めない購入日など）があれば取り込まない。削除はできない（状態を「廃棄」にする）。「履歴」シートは参照用で取り込まない（`instruments_xlsx.py`）
  - 温度計など他のシートを足すときは `instruments.py` の `SHEETS` に列の対応を追加する
  - `python import_xls.py --reset` は DB ごと作り直すので、その後に `python instruments.py` を流し直す
- **プラ点検**: 紙の「プラスチック部品チェック表」（前工程／後工程／タレ工程 チェック表フォルダ）を取り込み、チェック表の 1 行ごとに始業時・終業時の ○ / × / －（稼働なし）を記入する。各行に Excel に貼ってあった写真と場所を表示し、タップで拡大。× は内容が必須。「確認・記録」で日ごとの実施状況と異常を確認者が確認し、月ごとの点検記録（紙と同じ形）を Excel に出力できる
  - **プラリスト**: 「プラ樹脂点検リスト 前工程／後工程／タレ工程.xls」（危害度分析の一覧）。チェック表の各行と紐づき、「チェック表にない行だけ」で点検漏れを探せる（`pla.py`）
  - **チェック表**タブ: 行・場所・写真（スマホで撮って追加できる。長い辺 1600px に縮めて保存）・プラリストとの紐づけを直す（`pla_sheets.py`）
  - 取り込み: `python pla.py`（プラリスト）→ `python pla_sheets.py`（チェック表。.xls の写真を読むため Excel で .xlsx に変換してから読む。Excel が入っている PC で実行）。どちらも `--replace` で入れ直し（点検記録のある分は残す）
  - 写真は `data/pla_photos/` に保存（バックアップは下の「バックアップ」を参照）
- **分析**: 年別の定期・不定期件数、設備別の停止・修理時間、故障内容のキーワード、設備別の故障件数

## 起動方法

```bash
pip install -r requirements.txt
python import_xls.py            # フォルダ内の *.xls をすべて data/maintenance.db に取り込む（初回のみ）
python app.py                   # http://<サーバーのIP>:5000/ で公開
```

- 取り込み直す: `python import_xls.py --reset`（アプリで入力したデータも消えるので注意）
- 部品の価格表を追加する: `python parts_catalog.py 前工程ライン部品一覧.xls`（`--replace` で同じファイルの分を入れ直す）。`--reset` のときは `〇〇部品一覧.xls` も自動で取り込む
- 一部のファイルだけ取り込む: `python import_xls.py 前処理1.xls 後処理1..xls --reset`
- ポート変更: 環境変数 `MAINT_PORT`、DB の場所: `MAINT_DB`

## 交換アラートのメール通知

平日の朝に `notify.py` を動かし、エリアごとの宛先へ 1 通ずつまとめて送る。

- **送る内容**: 新しく「期限超過」「まもなく（14日以内・稼働時間残り2割）」に入った定期項目と、研磨上限が近い部品
- **繰り返し防止**: 一度送った項目は記録し、毎朝は送り直さない。期限を過ぎたまま残っている項目は週 1 回（既定は月曜）まとめて催促する。実施を記録して次の周期に入れば、また通知対象になる
- **宛先**: アプリの「通知設定」でエリアごとに登録する。「全エリア共通」に入れた宛先には全エリアの通知が届く。宛先のないエリアは送らずに警告を出す

### 設定手順

1. `notify.ini.example` を `notify.ini` にコピーし、`[smtp]` の `host` と `from`、`[app]` の `url` を入れる
   - Notes（Domino）の場合は Domino サーバーの SMTP（通常ポート 25）。社内からのリレーを許可してもらう必要があるので、**サーバー名・差出人アドレス・許可の有無を情報システム部門に確認する**
2. アプリの「通知設定」で宛先を登録し、「テスト送信」で届くことを確認する
3. 「今送るとどうなるか見る」で内容を確認する
4. **初回の一斉送信を防ぐ**: 取り込み直後は過去データで多数が期限超過になっている。定期項目の前回実施日を直すか、次のコマンドで今あるアラートを通知済みにしてから始める
   ```bash
   python notify.py --init
   ```
5. タスクスケジューラに登録する（例: 平日 7:30）
   ```bat
   schtasks /Create /TN "設備保全_交換アラート" /SC WEEKLY /D MON,TUE,WED,THU,FRI /ST 07:30 ^
     /TR "\"C:\Python312\python.exe\" \"D:\setsubi\notify.py\""
   ```
   （python.exe とアプリのパスはサーバーに合わせる。サーバーにログインしていなくても動くよう「ログオンしているかどうかにかかわらず実行」にする）

### コマンド

| コマンド | 内容 |
|---|---|
| `python notify.py` | 送信（土日は何もしない。`--force` で送る） |
| `python notify.py --dry-run` | 送らずに内容を表示 |
| `python notify.py --init` | 今あるアラートを通知済みにする |
| `python notify.py --test 宛先` | テストメールを 1 通送る |

## バックアップ

`backup.py` で `data` フォルダ（DB と点検写真）をサーバーの共有フォルダへコピーする。アプリを動かしたままでも実行できる（DB は SQLite のバックアップ機能で写すので、書き込み中でも壊れない）。

```bash
python backup.py \\fileserver\share\setsubi_backup            # 保存先を指定
python backup.py \\fileserver\share\setsubi_backup --keep 60  # DB を 60 世代残す（既定 30、0 で全部）
```

- 保存先に `db/maintenance_日時.db`（世代バックアップ。古いものから消す）・`pla_photos/`（追加・変更された写真だけコピー。アプリで消した写真も残す）・`record_files/`（作業記録の添付ファイル。コピーの仕方は写真と同じ）ができる
- 環境変数 `MAINT_BACKUP_DIR` を設定すれば保存先を省略できる
- 現在の運用: タスク「設備保全_バックアップ」で毎日 12:00 と 17:30 に `\\SV-NAR\KANSAIBF_DATA\03施設設備の保守点検\メンテナンスアプリバックアップ` へ保存している。その時刻に PC が止まっていた場合は、次に起動したときに実行される
- タスクスケジューラに登録する。共有フォルダに書き込める **ドメインユーザー** で「ログオンしているかどうかにかかわらず実行」にする（SYSTEM アカウントではネットワークの共有フォルダに書けない）
  ```bat
  schtasks /Create /TN "設備保全_バックアップ" /SC DAILY /ST 18:00 ^
    /TR "\"C:\Python312\python.exe\" \"D:\setsubi\backup.py\" \\fileserver\share\setsubi_backup"
  ```
- **戻すとき**: アプリを止め、戻したい世代の `.db` を `data/maintenance.db` に、`pla_photos/`・`record_files/` を `data/` の同じ名前のフォルダにコピーしてから起動する

## Excel 取り込みのルール

- 1 シート = 1 設備。「実施年月日」の見出し行と「設備名」の行を探して位置を合わせるので、取引業者欄が 2 段あるシート（ボイラー等）も読める
- 取り込まないシート: 「原紙」で始まるひな形、記録簿の書式でないシート（資産一覧・研磨管理表・空シート）、履歴のない「(2)」付きの複製シート
- 「旧」で始まるシートの設備は **廃止** として登録する
- シート名を **通称**（現場での呼び名）として残し、台帳ではこちらを大きく表示する。正式名は設備名欄の値
- **種類**（肉処理、玉葱、成型、包装・充填・計数など）は通称と正式名のキーワードから自動で付ける（`db.py` の `CATEGORY_RULES`）。違っていれば設備情報の編集から直せる
- 設備名欄が空のシートはシート名を設備名にする
- 日付:
  - Excel 日付・`23.1.28`・`18,5,20`・`2017/11/21、22`（期間は初日を採用）は通常の日付として読む
  - `2020.5月` のような月まで・`2015年` のような年だけの表記は月初・年初として並べ、**要確認** の印を付ける
  - 読めない表記（`20.18.5.8` など）・日付なし・前の行より大きく遡る日付も **要確認**
- 「実施稼働時間」欄（後処理は「実施修理時間」）→ **停止・修理時間（分）**。数字だけ・`○○分`・`停止4時間`・`10:00~14:00`・`660(停止305)` などを分に換算する。`○○h` は部品の稼働時間として扱う
  - 元の Excel ではこの欄に「ライン停止時間」と「修理にかかった時間」が混在しているため、どちらかに限定した集計はできない
- 備考に書かれた `稟議 (280万)` などは費用として読み取る
- 取引業者は「株式会社」「・」などの表記ゆれをまとめて 1 社にする
- 定期項目・部品の初期値は前処理1.xls の内容から作った **仮設定**（`import_xls.py` の `RULE_SEEDS` / `PART_SEEDS`）。現場で確認したうえで画面から修正すること

## 確認が必要なデータ

- 日付が要確認の履歴が 27 件ある（作業計画/履歴の「日付要確認のみ」で一覧できる）
- 同じ設備No が 2 シートにあるもの: G003（ミウラボイラー / ミウラボイラー 新）は両方とも稼働として登録している。K021・K201・K204 は「旧」シートの方を廃止にしている
- 設備No が未採番の設備が多い（X線・金検はほぼ全部）

## プロトタイプとしての制約

- ログイン機能はない。記入者は画面右上の欄に入力する（ブラウザに保存される）
- 承認フローは未実装。通知はメール（SMTP）のみ
- 取り込んだ履歴は 2025 年までなので、日数基準の定期項目はほぼ「期限超過」と表示される
- 定期項目は前処理の 19 項目しか登録していない。他のエリアは画面から追加する
- アワーメーターは手入力。前回実施時の値は、定期項目に紐づけた作業を完了で保存したときに記録される
